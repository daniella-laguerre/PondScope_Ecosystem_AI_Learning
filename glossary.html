Artificial intelligence
glossary

Short, industry-standard definitions for common AI / ML terms. Teaching metaphors used in this site (pond, notebook) are noted where they map.

Foundations

Artificial intelligence (AI)
Systems that perform tasks associated with human intelligence—perception, language, planning, or decision-making—usually by learning patterns from data rather than only following hand-written rules.
Machine learning (ML)
A subset of AI in which models improve performance on a task by fitting parameters to examples (or rewards), instead of being fully programmed for every case.
Deep learning
ML using multi-layer neural networks. “Deep” refers to many stacked layers of learned transformations.
Neural network
A model composed of interconnected units (neurons) organized in layers. Each connection has a learnable weight; nonlinear activations let the network approximate complex functions.
Parameter / weight
A number inside the model that is adjusted during training. Modern language models often have billions of parameters.
Activation
The numerical output of a neuron or layer for a given input. Intermediate activations are often inspected for interpretability and debugging.
Embedding
A dense vector representation of a discrete item (token, word, image patch). Nearby embeddings usually mean similar meaning or use.
Token
The atomic unit a language model reads and writes—often a subword piece, not necessarily a full word. Tokenization converts text into token IDs.
Vocabulary
The finite set of tokens the model knows. The output layer typically scores every vocabulary entry to pick the next token.
Representation / latent
An internal vector (or tensor) that encodes information the model has extracted so far. Not always human-readable.

Architectures

Feed-forward network (MLP)
Layers that transform a vector with linear maps and nonlinearities, usually without recurrence. In Transformers, the MLP block sits beside attention in each layer.
Recurrent neural network (RNN)
A network that updates a hidden state as it reads a sequence step by step. Memory size is fixed; long-range exact recall is hard. Pond metaphor: fixed-size evolving state.
LSTM / GRU
RNN variants with gates that control what to forget, write, and read. LSTM has a separate cell state; GRU combines gates more compactly.
Transformer
Architecture built on attention and feed-forward blocks (Vaswani et al., 2017). Dominant for large language models. Processes sequences with parallelizable attention rather than pure step-by-step recurrence.
State-space model (SSM)
Sequence model that maintains a dynamical state updated by structured linear (or selective) recurrences, often derived from continuous-time systems. Examples: S4, Mamba. Pond metaphor: continuous pond sampled once per token.
Mamba
A selective SSM architecture in which the state update depends on the current input, aiming for Transformer-like quality with linear-time sequence processing.
Hybrid model
An architecture that mixes mechanisms—e.g. mostly SSM/recurrent layers plus occasional attention—to balance constant-cost continuity with exact retrieval.
Mixture of experts (MoE)
A model that routes each token (or example) to a subset of specialist “expert” subnetworks via a learned router, increasing capacity without always running every parameter.
Encoder / decoder
Encoder maps input into representations; decoder generates outputs (often conditioned on the encoder). Many LLMs are decoder-only: they generate left to right from a prompt.
Diffusion model
Generative model that learns to reverse a noise process, widely used for images. The evolving noisy latent is another form of temporary state.

Memory & attention

Attention
A weighted lookup: a query is compared to keys; the resulting weights blend values. Lets the model focus on relevant positions or features. Notebook metaphor: look up entries in a growing record.
Self-attention
Attention where queries, keys, and values all come from the same sequence (each position can attend to others in that sequence).
Cross-attention
Attention where queries come from one stream (e.g. decoder) and keys/values from another (e.g. encoder or image features).
Multi-head attention (MHA)
Several attention heads run in parallel with different projections; their outputs are concatenated. Heads can specialize on different relations or distances.
Key–value cache (KV cache)
At inference, stored keys and values for past tokens so the model need not recompute them every step. Memory grows with context length.
Context window
The maximum span of tokens the model can attend to (or otherwise condition on) in one forward pass / generation session.
Positional encoding / position bias
Signals that tell the model token order. Absolute encodings, relative biases (e.g. T5), and ALiBi are common approaches. Pure RNNs/SSMs often get order “for free” from sequential updates.
Retrieval-augmented generation (RAG)
Fetching external documents or facts and inserting them into the prompt (or conditioning path) so the model can ground answers beyond its weights.

Training

Loss function
A scalar that measures how wrong the model’s predictions are. Training minimizes average loss (e.g. cross-entropy for next-token prediction).
Gradient descent / backpropagation
Compute how the loss changes with respect to each weight (gradients), then update weights to reduce loss. Backpropagation applies the chain rule through the network.
Learning rate
Step size for weight updates. Too large: unstable training. Too small: slow progress.
Batch / minibatch
A group of examples processed together to estimate the gradient. Larger batches are smoother but cost more memory.
Epoch
One full pass through the training dataset (or a defined data schedule).
Overfitting
Fitting the training data so closely that performance on new data suffers. Detected by watching held-out validation metrics.
Regularization
Techniques that discourage overfitting—e.g. weight decay, dropout, early stopping, data augmentation.
Fine-tuning
Further training a pretrained model on a narrower dataset or task so it adapts without training from scratch. Pond: reshaping or digging a hollow in the land — see metaphor reference.
LoRA / adapter
Parameter-efficient fine-tuning: small trainable modules (or low-rank updates) are added while most base weights stay frozen. Pond: a place (a pond dug in the land), not a training method — any post-training method can be applied to an adapter.
Pretraining
Large-scale training (often next-token or masked prediction) that builds general capabilities before specialization. Pond: forming the land before anyone digs.
Teacher forcing
During training, feed the model the correct previous token rather than its own prediction, stabilizing sequence learning.

Post-training
The family of procedures after pretraining that adapt a model for instruction-following, preferences, or checkable tasks (SFT, preference optimization, RL with verifiable rewards, etc.). Distinct from the runtime hidden state.
SFT (supervised fine-tuning)
Training on demonstration pairs (prompt → desired completion) with a supervised loss, usually next-token cross-entropy. The model imitates labeled examples. Pond: digging to a handed-over blueprint.
Rejection sampling / best-of-N
Generate several candidates, score them, and keep the best. At inference this need not update weights; survivors can also be reused as new SFT data. Pond: dig several ponds, keep the best one.
STaR (Self-Taught Reasoner)
A bootstrap loop: generate rationales/answers, keep those that reach a correct outcome, and fine-tune on the survivors — rejection sampling turned into more training data.
RLHF (reinforcement learning from human feedback)
Collect human preference comparisons, train a reward model on them, then optimize the policy (often with PPO or similar) to raise reward while staying near a reference model. Pond: reshaping to a survey via a surveyor — optimizing a model of preference, not people directly.
Reward model (RM)
A model trained to score outputs the way preference labels would. Used as a stand-in for human judgment during RLHF-style training. Pond: the surveyor.
Reward hacking / overoptimization
The policy exploits quirks of the reward model (or proxy) and scores highly while becoming less useful to humans. Structural risk when optimizing a proxy surveyor for too long.
KL penalty (KL regularization)
A term that penalizes the trained policy for diverging too far from a reference model (often the SFT model), limiting collapse into high-reward but degenerate outputs. Pond: the leash that keeps the digger from leaving the site.
RLAIF (reinforcement learning from AI feedback)
Like RLHF, but preference labels (or critiques) come from an AI judge rather than humans. Cheaper and scalable; inherits the judge model’s biases. Pond: the survey is conducted by another pond.
Constitutional AI
Alignment via a written list of principles: the model critiques and revises its own outputs against those rules, then trains on the revised data (often with RLAIF). Principles are inspectable. Pond: posted rules the surveyor must obey.
DPO (direct preference optimization)
Preference fine-tuning that updates the policy directly from preferred/dispreferred pairs without a separate reward model and RL loop. Widely used in open fine-tunes. Pond: reshape from the comparison notes — skip hiring a surveyor.
IPO (identity preference optimization)
A preference objective related to DPO that better controls how far a single comparison can push the policy when preferences are nearly unanimous. Pond: don’t dig a canyon on a unanimous vote.
KTO (Kahneman–Tversky optimization)
Alignment from unpaired desirables/undesirables (thumbs up/down) rather than required A/B pairs, drawing on prospect-theory style asymmetry between losses and gains. Pond: reshape from lone reactions.
RLVR (reinforcement learning from verifiable rewards)
RL where the reward is a checkable fact (unit test, exact answer, proof checker) rather than a preference model. No surveyor to fool when the checker is sound. Pond: does the water reach the sea? Only works where a sea exists.
Outcome-only RL
Reward based solely on the final result (correct/incorrect), with no supervision of intermediate steps. Can discover novel solution paths; weak on credit assignment and can reward lucky shortcuts. Pond: only the sea is checked.
Process reward model (PRM)
A scorer for intermediate reasoning steps, not only the final answer. Improves credit assignment; reintroduces a step-level judge. Pond: inspect at every bend, not only at the mouth.
Self-play / iterated self-improvement
The model generates and competes against or judges copies of itself, then trains on the outcomes, repeating. Strong with hard win conditions; can homogenize without one. Pond: two ponds feeding each other until the shoreline moves.
Preference pair
A labeled comparison of two outputs for the same prompt (A preferred over B). The usual data unit for RLHF reward modeling and for DPO/IPO.
Reference model
A frozen (or slowly updated) baseline policy used in RLHF/DPO-style training to measure divergence and keep the new policy from drifting arbitrarily far.

Generation & inference

Inference
Running a trained model to produce outputs (no weight updates). Distinct from training.
Autoregressive generation
Producing a sequence one token at a time, each conditioned on what was already generated (and the prompt).
Logits
Raw scores over the vocabulary before softmax. Higher logit ⇒ model favors that token more.
Softmax / probability
Converts logits into a probability distribution over tokens. Sampling or argmax chooses the next token from that distribution.
Temperature
Softmax sharpness control. Lower → more peaked / deterministic; higher → more random / diverse.
Top-k / top-p (nucleus) sampling
Decode only from the k most likely tokens, or from the smallest set whose cumulative probability exceeds p. Limits low-probability noise.
Greedy decoding
Always pick the single highest-probability next token. Fast and deterministic; can be repetitive.
Prompt
The input text (and optionally system instructions) that conditions generation.
Hallucination
Fluent output that is factually wrong or unsupported. Not a separate module—an emergent failure mode of generative models.

Evaluation & interpretability

Training / validation / test split
Separate data for fitting, tuning, and final reporting so scores reflect generalization, not memorization of the train set.
Accuracy / exact match
Fraction of predictions that fully match the target (token, label, or sequence). Simple but strict for generation.
Perplexity
How “surprised” a language model is by held-out text; lower is better. Related to average next-token loss.
Ablation
Remove or disable a component (layer, head, branch) and measure the performance drop to test whether it was necessary.
Probe
A simple model (often linear) trained to read a property from activations. Shows decodability, not necessarily that the network uses that property.
Activation patching / causal tracing
Swap internal activations from a donor run into a recipient run to test whether that state causes a behavior change.
Double dissociation
Classic causal pattern: intervention A hurts function X but not Y; intervention B hurts Y but not X. Stronger than a single selective failure.

Systems & practice

GPU / accelerator
Hardware optimized for parallel linear algebra. Most deep learning training and large-model inference runs on GPUs or similar chips.
Quantization
Storing and/or computing with lower-precision numbers (e.g. 8-bit, 4-bit) to reduce memory and often speed, with some quality trade-off.
Checkpoint
A saved snapshot of model weights (and sometimes optimizer state) at a point in training, used for resume, deploy, or best-model selection.
Latency / throughput
Latency: time from request to a usable response. Throughput: tokens or requests completed per unit time. Both matter in production. See also time to first token under Issues.
Agent
A system that uses a model to plan and act—calling tools, browsing, or updating memory—over multiple steps toward a goal.
Tool use / function calling
Letting a model request external actions (search, code execution, APIs) whose results are fed back into the conversation.
MCP (Model Context Protocol)
A standard way for applications to expose tools and context to AI models through a shared protocol, rather than one-off integrations.

Issues & failure modes

Operational and product problems that show up when models leave the lab. Hallucination and overfitting are defined in Generation and Training above — not repeated here. Latency / throughput is defined under Systems.

Time to first token (TTFT)
How long until the model emits the first output token. Often what users feel as “thinking delay,” even when the rest of the answer streams quickly.
Try it in Issues Lab →
Token overconsumption
Using far more tokens than the task needs—verbose answers, oversized prompts, redundant history, or unnecessary tool loops—raising cost and often latency.
Try it in Issues Lab →
Context bloat
Prompt and conversation history grow so large that cost rises, quality drops, or the context window is exhausted. Related to token overconsumption, but focused on the filled window itself.
KV-cache memory pressure
Long contexts make the stored key–value cache huge, limiting concurrent users, forcing shorter windows, or increasing serving cost. (The KV cache mechanism is defined under Memory.)
Cold start
Extra delay when a model or server must load into memory (or scale from zero) before handling the first real request.
Confabulation
Inventing plausible-sounding details to fill gaps in knowledge or context. In product language often grouped with hallucination; here it stresses gap-filling rather than outright false claims about known facts.
Grounding failure
The model ignores or misuses provided documents, retrieval results, or tool outputs and answers from parametric memory instead—or cites sources incorrectly.
Try it in Issues Lab →
Instruction following failure
The model misses stated constraints: required format, length, steps, tone, or banned content, even when the request was clear.
Tool-use error
Wrong tool chosen, invalid arguments, failed calls mishandled, or tool results misread—so the final answer is wrong even if the base model is capable.
Cascading agent error
In a multi-step agent run, one early mistake poisons later plans and tool calls, compounding into a large failure from a small start.
Nondeterminism
The same prompt yields different outputs across runs because of sampling, batching, concurrency, or backend routing—harder to test, reproduce, and audit.
Jailbreak / prompt injection
Inputs designed to override system rules or sneak instructions through untrusted content (web pages, documents, tool output) so the model does something it was told not to.
Data leakage
The system reveals secrets, private user data, or sensitive text memorized from training—through answers, logs, or side channels.
Toxic / harmful output
Content that is abusive, dangerous, illegal to assist with, or otherwise violates safety policy.
Bias
Systematic unfair or skewed behavior across groups, dialects, topics, or regions—often reflecting imbalances in data or feedback.
Sycophancy
The model agrees with the user (or flatters them) even when the user is wrong, instead of correcting errors.
Catastrophic forgetting
Fine-tuning or continued training improves a new task but erases or degrades older capabilities the model previously had.
Distribution shift
Real traffic differs from the data used for training or evaluation, so lab metrics stop predicting production quality.
Reward hacking
The model optimizes a proxy score (e.g. “sounds helpful,” passes an automatic judge) without truly solving the underlying task. See also reward hacking / overoptimization under metaphor reference.
Mode collapse
Outputs become repetitive or narrowly similar—limited diversity of answers or styles—more often discussed for some generative setups, but also seen as stuck patterns in chat models.
Truncation
Input or output is cut off by max-token or context limits mid-thought, producing incomplete answers or silently dropped instructions.
Repetition loop
The model gets stuck repeating phrases, lists, or structures instead of progressing to a finish.
Stale knowledge
Parametric knowledge is outdated; the model does not know recent facts unless retrieval, tools, or fresh fine-tuning supply them.
Overrefusal
The model refuses safe, allowed requests because safety or policy filters are too aggressive.
Underrefusal
The model answers when it should refuse—a safety miss on disallowed or dangerous requests.
