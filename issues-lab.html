Builds on lesson 01 · The Pond

Latency as slow pond steps

In the pond lesson, time advances once per token. TTFT is the wait before the first step; streaming is later steps. Cold start = loading poles before any ripple moves.

See where it hits the model / memory

Open the pond Pipeline already streaming slowly — each token is one step. Compare with the notebook lesson: both step once per symbol.

Memory note: Slow TTFT / cold start often does not mean the pond learned the wrong poles. It is usually a serving / stepping delay (load, queue, generate one token at a time). If accuracy after Fit is fine, treat latency as infrastructure timing, not a model bug.

Grounding as heads on the page

With retrieval off, only the pond compressed memory answers — it confabulates. With retrieval on, multi-head attention looks up the notebook and cites it.
